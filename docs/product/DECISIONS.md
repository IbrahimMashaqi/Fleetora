# Fleetora — Owner Decisions

- **Approved:** 2026-11-25 by the product owner.
- **UX-01: one searchable Combobox pattern for all record pickers (owner, 2026-11-27).** Draft text stays inside the shared `components/ui/combobox`; typing does not apply/clear a selection, navigate, refresh the route or remount the input. Suggestions use approximately 250 ms debounced, authenticated route-handler/fetch reads, server-side Arabic normalization and trusted tenant context. Click/Enter selects; explicit clear clears. List searches update results in place. Short status/action/role enums and free-form creation/contact/address fields are not record pickers.

- **Phase 1 clarification approved:** 2026-11-26 by the product owner: OD-13 also blocks adjustments for PENDING merchants (no money of any kind before ACTIVE); OD-02 company currency changes remain blocked, with the controlled transition deferred.
- **Source of each conflict:** [RECONCILIATION.md](RECONCILIATION.md) (OD-01..OD-13).
- **Phase 2 split approved (2026-11-26):** Phase 2a implements the four built-in staff roles (one role per user), explicit Worker-linked driver phone/password identity, suspension and security/offboarding access (BR-042 built-in part, BR-043, BR-035, BR-117, BR-118). Company custom roles (BR-042 custom part) and delegation (BR-044) are deferred to Phase 2b. No driver app is included.
- **Phase 2a staff boundary:** COMPANY_ADMIN retains full company access; OPERATIONS manages parcels, pickups, assignments, drivers and warehouse operations without finance, pricing administration or staff/settings; ACCOUNTANT retains its existing finance permissions and parcel reads; WAREHOUSE handles receipt, warehouse custody and return stages with parcel reads. Pricing, staff/roles and company settings remain COMPANY_ADMIN only. Existing identities are not rewritten or promoted. The existing admin-only adjustment permission is preserved pending clarification of the conflicting accountant-adjustment request.
- **Phase 2a driver identity contract:** Admin/Operations explicitly invites an existing company Worker, never matches by phone/name. Phone/password login uses normalized +970/+972 numbers and the existing throttling/client-source rules. Driver phones are globally unique and accounts link 1:1 to a tenant-checked Worker; existing Workers remain unlinked. Invitation links use HTTPS `/driver/activate#token=...`; hashed, expiring, single-use, revocable tokens; copy/wa.me sharing only. Recovery is an administrator re-invitation. Suspension stops new tasks without removing login or existing obligations; security revocation immediately blocks sessions/login. Offboarding stops new tasks with optional access revocation; final settlement remains deferred.
- **Authority:** these decisions resolve the listed conflicts between the approved sources and the current code. They sit alongside the authority order in [README.md](README.md); they do not add rules beyond those cited.
- **Development activation exception approved (2026-11-27):** Driver, merchant and staff activation links may use HTTP only when backend `NODE_ENV != production` and the URL host is loopback (`localhost`, `127.0.0.1`, `::1`). All other activation origins require HTTPS; production always requires HTTPS. This qualifies the HTTPS-only development limitation above. Tokens remain in the fragment, never the query. The frontend uses server-only `FLEETORA_ACTIVATION_ENV` metadata matching backend `NODE_ENV` because Next's production build mode also serves local Docker development; Compose derives both from `BACKEND_NODE_ENV`. Without that metadata the frontend uses its own `NODE_ENV` and remains HTTPS-only in production.
- **"Docs win"** means the cited approved rules are implemented as written and the current code must be changed in the target phase. Until then, the existing code stays as is.
